## 🧪 Testing Strategy

### 1. Unit Testing (`tests/unit/`)

각 모듈의 독립적인 기능을 검증합니다. `pytest`를 사용합니다.

*   **Prompt Template Test**: 템플릿 렌더링 시 변수가 올바르게 채워지는지 확인.
*   **Parser Fallback Test**: Primary 실패 시 Secondary가 호출되는지 Mocking으로 검증.
*   **Pydantic Validation Test**: 잘못된 데이터 입력 시 Validation Error 발생하는지 확인.

```python
# tests/unit/test_parser.py example
def test_parser_fallback(mocker):
    mocker.patch('src.dataflows.parsers.vlm.parse', side_effect=Exception("API Error"))
    mock_secondary = mocker.patch('src.dataflows.parsers.pymupdf.parse')
    
    robust_pdf_parser("test.pdf")
    
    assert mock_secondary.called
```

### 2. Integration Testing (`tests/integration/`)

LangGraph 워크플로우의 부분 집합(Subgraph)을 테스트합니다.

*   **Analyst Parallelism**: 3개의 Analyst가 병렬로 실행되고 State에 모두 결과가 남는지 확인.
*   **Debate Flow**: Bull -> Bear -> Synthesizer 순서로 데이터가 잘 전달되는지 확인.
*   **Loop Limit Test**: Debate가 최대 3라운드까지만 돌고 Synthesizer로 넘어가는지 확인.

### 3. End-to-End Testing

실제 데이터(샘플 PDF)를 넣고 최종 리포트 생성까지 확인합니다.

*   **Data Consistency**: 원본 PDF의 내용(숫자 등)이 최종 리포트에 정확히 반영되었는가?
*   **Hallucination Check**: 없는 사실을 지어내지 않았는가? (Quality Check Agent 활용)

## 🛠 Development Workflow Guidelines

1.  **State Schema First**: 코딩 전에 `ReportState`가 필요한 데이터를 담을 수 있는지 먼저 확인하십시오.
2.  **Mocking LLM**: 테스트 시에는 비용 절감을 위해 Mock LLM을 사용하거나 `fake-llm` 모드를 활용하십시오.
3.  **Atomic Commits**: 각 Step(예: 0.1 완료)마다 커밋하여 추적 용이성을 확보하십시오.
4.  **Logging**: `execution_trace` 리스트에 중요 단계마다 로그 문자열을 `append` 하십시오.
