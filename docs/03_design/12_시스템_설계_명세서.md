## 🏗 1. Global State Architecture

LangGraph의 `TypedDict`를 활용하여 전역 상태(Global State)를 엄격하게 관리합니다.

### 1.1 Core State Class

```python
# src/pipeline/schema.py

from typing import TypedDict, List, Dict, Optional, Annotated, Literal
import operator

class ReportState(TypedDict):
    """
    워크플로우 전체에서 공유되는 중앙 상태 객체
    """
    # ----------------------------------------------------
    # 1. Inputs (사용자 입력)
    # ----------------------------------------------------
    query: str                              # 사용자 질문
    target_companies: List[str]             # 분석 대상 기업 (예: ["삼성전자", "SK하이닉스"])
    report_type: Literal["scan", "deep"]    # 분석 깊이 ("scan": Quick, "deep": Deep)
    document_path: Optional[str]            # (Optional) 분석할 PDF/문서 경로

    # ----------------------------------------------------
    # 2. Graph Data (Knowledge Graph)
    # ----------------------------------------------------
    kg_updates: Annotated[List[Dict], operator.add] # 새로 생성된 노드/엣지 (Reducer: append)
    schema_errors: List[str]                        # Quality Check에서 발견된 에러
    
    # ----------------------------------------------------
    # 3. Retrieval Results (RAG)
    # ----------------------------------------------------
    graph_rag_results: Dict[str, Any]       # Neo4j 검색 결과 (Entities, Relations, Paths)
    news_events: List[Dict]                 # 관련 뉴스 이벤트 (검색된 것)
    
    # ----------------------------------------------------
    # 4. Analysis & Debate (Multi-Agent State)
    # ----------------------------------------------------
    # Analyst Agents Output
    fundamental_analysis: Optional[str]     # 재무 분석 결과
    trend_analysis: Optional[str]           # 트렌드(SAX) 분석 결과
    event_analysis: Optional[str]           # 이벤트 임팩트 분석 결과
    
    # Debate State
    bull_argument: Optional[str]            # Bull 에이전트 논리
    bear_argument: Optional[str]            # Bear 에이전트 논리
    debate_turn_count: int = 0              # 토론 라운드 카운트 (Max 3)
    synthesis_verdict: Optional[str]        # Synthesizer 종합 판단
    
    # ----------------------------------------------------
    # 5. Metadata & Provenance
    # ----------------------------------------------------
    retry_count: int                        # 재시도 횟수 (Infinite Loop 방지)
    execution_trace: Annotated[List[str], operator.add] # 실행 로그
    critical_paths: List[str]               # 근거로 사용된 핵심 경로 (Provenance)
    final_report: Optional[str]             # 최종 생성된 마크다운 리포트
```

### 1.2 Data Models (Pydantic)

데이터의 일관성을 위해 Pydantic 모델을 사용하여 I/O를 검증합니다.

```python
# src/models/nodes.py

from pydantic import BaseModel, Field
from enum import Enum

class NodeType(str, Enum):
    COMPANY = "Company"
    PRODUCT = "Product"
    EVENT = "Event"
    METRIC = "Metric"
    TREND = "Trend"

class Entity(BaseModel):
    name: str
    type: NodeType
    properties: Dict[str, Any] = Field(default_factory=dict)

class RelationType(str, Enum):
    COMPETITOR_OF = "COMPETITOR_OF"
    SUPPLIER_OF = "SUPPLIER_OF"
    AFFECTS = "AFFECTS"
    HAS_METRIC = "HAS_METRIC"

class Triplet(BaseModel):
    subject: str
    predicate: RelationType
    object: str
    weight: float = 1.0
```

## 🧩 2. Node Interface Specification

각 노드(Node)의 입력과 출력을 명확히 정의하여 의존성을 관리합니다.

### 2.1 Data Ingestion Nodes

#### `Node: GeminiPDFParser` (Phase 0.4) ⭐ **Production**
- **Role**: PDF에서 Knowledge Graph 직접 추출 (원스텝 파이프라인)
- **Strategy**: **Native Structured Output** (Gemini PDF → KG JSON)
- **Input**: `state.document_path`
- **Output**: 
    - `knowledge_graph`: KnowledgeGraph (Pydantic 모델)
    - `raw_json`: dict
    - `metadata`: dict
- **Function Signature**:
    ```python
    def gemini_pdf_parser_node(state: ReportState) -> Dict:
        # 1. client.files.upload(pdf_path) -> URI 획득 (캐싱 적용)
        # 2. client.models.generate_content(contents=[uri, prompt]) -> Structured Output 추출
        # 3. Parse to KnowledgeGraph Pydantic model
        return {"knowledge_graph": kg, "raw_json": json_data}
    ```
- **API 활용 상세**:
    - **URI 기반 처리**: Base64 인코딩 제한 우회를 위해 Files API 필수 사용
    - **MIME 자동화**: 업로드 시 `mimetypes`를 통한 동적 타입 지정
    - **캐싱 전략**: 세션당 파일 경로-URI 매핑 정보를 싱글톤으로 유지하여 재업로드 방지
- **Optimization**: Batch API 활용 (비용 50% 절감)

#### `Node: VLMParser` (Phase 0.4 - 백로그)
- **Role**: PDF 차트/그래프 상세 분석 (연구 단계용)
- **Strategy**: **Hybrid** (PyMuPDF + Gemini Vision)
- **현재 상태**: 백로그 (특수한 차트 분석 필요 시에만 사용)
- **Input**: `state.document_path`
- **Output**: `parsed_text`, `extracted_charts`

#### `Node: KGConstructionAgent` (Phase 1 - **Orchestrator**)
- **Role**: **Multi-Agent Orchestrator** - 모든 Parser Agent 실행 및 JSON → Neo4j 파이프라인 총괄
- **책임**:
  1. 데이터 소스 자동 스캔 및 분류
  2. 적절한 Parser Agent 선택 및 실행 오케스트레이션
  3. 파싱 결과(JSON) 수집 및 병합 (KGMerger 사용)
  4. EntityNormalizer를 통한 정규화
  5. Neo4j 주입 및 결과 리포트 생성
- **데이터 스캔 규칙 (Glob Pattern)**:
  - PDF: `reports/**/*.pdf`, `ir/**/*.pdf`
  - Price: `price/*.csv`
  - DART: `DART/` (디렉토리 루트)
  - News: `news/*.csv`
  - Macro: `macro/*.csv`
  - Fund: `fund/*_fundamentals.csv`
- **Sub-Agents**:
  - `PDFParserAgent` ✅ - GeminiPDFParser 래핑
  - `PriceParserAgent` ✅ - 주가 CSV 파싱
  - `DARTParserAgent` ✅ - 공시 데이터 파싱
  - `NewsParserAgent` ✅ - 뉴스 이벤트 파싱
  - `MacroParserAgent` ✅ - 거시경제 지표 파싱
  - `FundParserAgent` ✅ - 펀더멘탈 파싱
- **Configuration**: Seed Ontology 사용 (Pydantic Enum 강제)
- **Optimization**: **Quick Model** (gemini-2.5-flash)
- **Input**: `data_sources: Dict` (또는 auto_scan=True)
- **Output**: 
    - `report`: Dict (파싱 통계, Neo4j 주입 결과)
- **Architecture**:
    ```
    KGConstructionAgent (Orchestrator)
      ├─► PDFParserAgent → JSON
      ├─► PriceParserAgent → JSON
      ├─► DARTParserAgent → JSON
      ├─► NewsParserAgent → JSON
      ├─► MacroParserAgent → JSON
      ├─► FundParserAgent → JSON
      └─► [Merge] → Normalize → Neo4j
    ```
- **Usage**:
    ```python
    agent = KGConstructionAgent()
    report = agent.construct_knowledge_graph(auto_scan=True)
    # → 모든 data/raw/* 자동 처리
    ```

### 2.1.1 Parser Agent 상세 명세

각 Parser Agent의 입력/출력, 전처리 과정, 조절 가능한 하이퍼파라미터를 명시합니다.

#### `Sub-Agent: PriceParserAgent`

**목적**: 주가 시계열 CSV → Knowledge Graph (Trend + Metric 노드)

**Input**:
- **파일**: `*.csv` (예: `005930.KS_prices.csv`)
- **필수 컬럼**: `date`, `close`
- **선택 컬럼**: `open`, `high`, `low`, `volume`

**전처리**:
1. 날짜 정렬 (오름차순)
2. 컬럼명 소문자 정규화
3. Ticker 추출 (파일명 기반)

**Output**:
- **Trend 노드** (1개): 전체 기간 SAX 패턴 요약
  - `ticker`, `period`, `pattern`, `trend_type`, `data_points`
- **Metric 노드** (샘플링): 최근 주가 데이터
  - `ticker`, `date`, `close`, `volume`, `open`, `high`, `low`
- **관계**: 
  - `Company-[:HAS_TREND]->Trend`
  - `Company-[:HAS_METRIC]->Metric`

**하이퍼파라미터** ⚙️:
```python
# 주가 샘플링
PRICE_SAMPLE_SIZE = 30  # 최근 N일 (기본: 30일)
PRICE_MIN_SAMPLES = 10  # 최소 샘플 수
PRICE_SAMPLE_RATIO = 0.1  # 전체의 10%

# SAX 변환
SAX_WINDOW_SIZE = 5  # 윈도우 크기
SAX_PAA_SIZE = 3  # PAA 세그먼트 수
SAX_ALPHABET_SIZE = 5  # 알파벳 크기 (a-e)

# 트렌드 분류 임계값
VOLATILITY_THRESHOLD = 0.05  # 변동성 임계값
UPWARD_THRESHOLD = 0.1  # 상승 추세 임계값 (10%)
DOWNWARD_THRESHOLD = -0.1  # 하락 추세 임계값 (-10%)
```

**데이터 레이어**: 100% 동적 (CREATE)

#### `Sub-Agent: DARTParserAgent`

**목적**: DART 공시 데이터 → Knowledge Graph (Company + Event + Metric)

**Input**:
- **파일**: `data/raw/DART/` 디렉토리 (3개 CSV)
  - `companies.csv`: ticker, corp_code, corp_name
  - `disclosure_states.csv`: ticker, date, title, type
  - `financial_states.csv`: ticker, period, revenue, operating_profit, net_income

**전처리**:
1. 3개 CSV 통합 로드
2. ticker → corp_name 매핑 생성
3. Entity 정규화 (EntityNormalizer 사용)
4. 날짜 파싱 (YYYY-MM-DD 형식)

**Output**:
- **Company 노드** (정적): 기업 기본 정보
  - `ticker`, `corp_code`, `corp_name`
- **Event 노드** (동적): 공시 이벤트
  - `ticker`, `date`, `event_type`, `title`, `disclosure_type`
- **Metric 노드** (동적): 재무 지표
  - `ticker`, `period`, `revenue`, `operating_profit`, `net_income`
- **관계**:
  - `Company-[:AFFECTED_BY]->Event`
  - `Company-[:HAS_METRIC]->Metric`

**하이퍼파라미터** ⚙️:
```python
# 샘플링 없음 (전체 데이터 사용)
# 공시: ~3,000건 전부 저장
# 재무: ~90건 전부 저장
```

**데이터 레이어**: 정적(Company - MERGE) + 동적(Event/Metric - CREATE)

#### `Sub-Agent: NewsParserAgent`

**목적**: 뉴스 CSV → Knowledge Graph (Event 노드)

**Input**:
- **파일**: `Semiconductor_News_Raw_*.csv`
- **필수 컬럼**: `title`, `date`
- **선택 컬럼**: `description`, `keyword`, `link`

**전처리**:
1. 날짜 파싱 및 검증
2. 날짜 기준 최신순 정렬
3. 샘플링 (최근 N건)

**Output**:
- **Event 노드**: 뉴스 이벤트
  - `date`, `event_type`, `title`, `description`, `keyword`, `link`, `time_decay_weight`
- **관계**:
  - `Company-[:AFFECTED_BY]->Event` (keyword → Company 매핑)

**하이퍼파라미터** ⚙️:
```python
# 뉴스 샘플링
NEWS_SAMPLE_SIZE = 100  # 최근 N건 (기본: 100건)
NEWS_MAX_TITLE_LENGTH = 200  # 제목 최대 길이
NEWS_MAX_DESC_LENGTH = 500  # 설명 최대 길이

# Time-decay 가중치
TIME_DECAY_HALFLIFE = 90  # 반감기 (일) - 90일 후 가중치 50%
TIME_DECAY_MIN_WEIGHT = 0.1  # 최소 가중치
```

**Time-decay 계산식**:
```python
import numpy as np
days_diff = (현재날짜 - 이벤트날짜).days
decay_weight = max(np.exp(-days_diff / TIME_DECAY_HALFLIFE), TIME_DECAY_MIN_WEIGHT)
```

**데이터 레이어**: 100% 동적 (CREATE)

### 2.2 Analysis Nodes (Phase 2.4 - Analyst Team)

이 노드들은 병렬로 실행됩니다 (`Map-Reduce` 패턴).

- **Role**: 시계열 패턴(SAX) 및 수급 분석
- **Model**: **Quick** (Gemini 2.5 Flash)
- **Input**: `state.graph_rag_results` (Trend 노드 위주)
- **Output**: `state.trend_analysis`

#### `Node: EventAnalyst`
- **Role**: 뉴스/이벤트의 임팩트 분석
- **Model**: **Deep** (Gemini 3 Pro)
- **Input**: `state.news_events`, `state.graph_rag_results` (Event 노드)
- **Output**: `state.event_analysis`

### 2.3 Debate & Synthesis Nodes (Phase 2.3)

#### `Node: BullAgent`
- **Role**: 긍정적 요소(기회) 강조 및 논리 전개
- **Model**: **Quick** (Gemini 3 Pro)
- **Input**: 
    - `fundamental_analysis`
    - `trend_analysis`
    - `event_analysis`
- **Output**: `state.bull_argument`

#### `Node: BearAgent`
- **Role**: 부정적 요소(리스크) 강조 및 방어 논리

- **Input**: (Bull과 동일)
- **Output**: `state.bear_argument`

#### `Node: Synthesizer`
- **Role**: Bull/Bear 주장을 변증법적으로 통합하고 최종 판단
- **Model**: **Deep** (Gemini 3 Pro)
- **Input**: `bull_argument`, `bear_argument`, `critical_paths`
- **Output**: `state.synthesis_verdict`

## 🔄 4. State Transition & Routing Logic

### 4.1 Conditional Edges

1. **Parser Fallback**: 실패 시 대체 파서로 재시도
2. **Quality Check Loop**:
    ```python
    def route_after_qc(state):
        if state['schema_errors'] and state['retry_count'] < MAX_RETRIES:
            return "retry_kg_construction"
        return "graph_rag_query"
    ```
3. **Analyst Parallelism**:
    - Query 질의 시 -> `[Fundamentals, Trend, Event]` 병렬 실행 -> `Debate`

4. **Debate Loop Control**:
    ```python
    def route_debate(state):
        # Bull -> Bear -> (Check) -> Bull ...
        if state['debate_turn_count'] < 3:
            return "bull" # Continue Debate
        return "synthesizer" # End Debate
    ```
